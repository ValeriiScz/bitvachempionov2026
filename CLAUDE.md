## 4. Решения по сайту
- Все новые турниры — в едином новом стиле DOVOD (база общая, цвета подстраиваются под стиль турнира). Старый «круглый» стиль не использовать.
- Сила игроков: по каждому игроку держим **ELO markery** и **MMR mafiastats**; свою систему оценки не строим.
- С 05–06.11.2026 основной — **MMR**: в списке игроков переключатель MMR/ELO (по умолчанию MMR), сила столов и соперники — по MMR-тирам. Тиры MMR = вероятность выхода в финал; L — только самые топы. Игрок без MMR на mafiastats — «новичок». Тиры mafiastats (silver/gold/diamond) не используем.
- Таблица игроков (ID mafgame/markery + ELO/MMR) хранится в данных — не собирать каждый раз заново.
- Цель: быстрое самообновление (live-результаты, ELO, гонка, календарь) с минимумом токенов.
- Закрытый раздел **«Лаборатория»** — для аналитических статей/разборов. К статьям: комментарии (ник без регистрации), реакции, счётчик просмотров (можно убрать, если не зайдёт).
- В планах: личный кабинет как на mafgame.
- MMR = основной `rating` mafiastats (включает и онлайн-игры; «только офлайн» API не отдаёт). Решение 10.11: оставляем — тиры и прогноз откалиброваны на нём; переходим, только если mafiastats даст офлайн-поле (тогда перекалибровка).
- GMC 664 (финал 14–15.11, Кёльн): финального стола нет — 18 игр, место по сумме; прогноз — шансы на места. Пока только MMR, ELO скрыт до перепроверки. Состав = подтверждённые на mafgame. «Дом» игрока на карте = город клуба на mafgame, ручные поправки (Грешник → Валенсия) — в сборщике mk664.
- Отменённый турнир убираем из `tournaments.js` (данные в `data/` не удаляем); неподтверждённые турниры на сайт не ставим.
- Новый турнир: после пуша `participants_{id}.json` дождаться коммита робота «MMR mafiastats: автообновление» (~15–20 мин) и только потом называть MMR состава. Пустой MMR у нового игрока до прогона ≠ «не найден». `mmrAvg`/`mmrN` на карточке робот считает сам (README, «Рейтинг состава»).
- **Составы на страницах набора (13.11):** `data/participants_{id}.json` незавершённых турниров робот «Обновление данных mafgame» (refresh_mafgame v1.4) сверяет с mafgame каждый прогон: новые игроки (MMR/ELO из `data/mmr.json` и реестра), выписавшиеся, заявка → подтверждён; `meta.roster_snap` = дата. Отозванные/отклонённые заявки не показываем. Архив не трогает.
- **Архив заморожен (решение 12.11):** MMR в составах завершённых турниров больше не обновляется — остаётся снимок на дату (`meta.ms_snap`, флаг `meta.ms_frozen`), на странице участников подпись «снимок DD.MM.YYYY · архив, не обновляется». Робот mafiastats v1.7 пропускает составы со `status: finished`. У турниров, закрытых до 03.11, ранних снимков нет — у них снимок 03.11.2026 (первый прогон робота).
- **ELO справочно (12.11):** опора — MMR (первая колонка, группы и сортировка по тиру MMR); ELO правее, с датой снимка. Свежий ELO по составам незавершённых турниров — робот «ELO markery» (вт/пт и при новом составе).
- **Плашка турнира (12.11):** «Кто едет» — 10 аватаров топа по MMR без ников (обводка = тир), «A/B/C и выше» цифрами; **сила состава** — значок (5 столбиков + слово: мягкий / ниже среднего / средний / выше среднего / экстремальный) на «Турниры», «Календарь», главной. Решение 12.11 (v1.9 робота): считается для ВСЕХ турниров календаря за окно (6 полных месяцев до текущего + текущий + будущие), без онлайна/отмен/командных; **две группы, сравниваются только внутри себя: рейтинговые (со звёздами, вкл. финалы серийников) и серии**; **поправка на размер**: шанс эталонного игрока тира A (MMR 1700) по модели MMR дойти до цели (≤12 человек — подиум, больше — финал топ-10), делённый на шанс при равных K/(N+1); меньше — жёстче; уровни по долям 20/40/60/80% в своей группе. Собирающиеся турниры (записано <95% ожидаемого) получают **прогноз**: оценка по уже записанным, как если бы турнир был на N записанных (мест в финале/тройке пропорционально меньше); пунктирная рамка и подпись «прогноз (20/40)»; прогноз встаёт в шкалу собранных составов, не сдвигая её; минимум 5 записанных с MMR (решение 12.11). Очки L3/S2/A1 и C+ — только в подсказке. Прошедшие замораживаются (`data/strength.json`, frozen). Данные для страниц — `data/strength.js`. Пересчёт: каждую ночь (refresh-data) и в прогонах робота MMR.
- **Интерфейс (дизайн-ревью 13.11):** общий слой `assets/dv-ui.js` (подключается из `share.js`, т.е. на всех страницах): на телефоне одно нижнее меню «Сейчас · Турниры · Календарь · Серии · Ещё» (кроме страниц турниров со своим `.tabbar`, смотровых и `?embed=1`); подписи не мельче 11 px и контраст не ниже 4.5:1 — правится автоматически; без синих вспышек и задержки тапа, плавные переходы между страницами. Плашка турнира — короткая: дата·город·звёзды, сила состава, игроки/MMR/приз, кто едет, одна главная кнопка. Всё нажимаемое — ≥40 px. Логотип mafgame — локальный `assets/mafgame-logo.svg`. Окно «установить приложение» — со 2-го визита.
- **Смотровая v2 (13.11):** слой `assets/watch-ui.js` во всех `watch*.html` (перед share.js), логику страницы не меняет — отключается удалением строки подключения. Телефон: эфир наверху, PiP только в «Один стол», плашка «Слежу: …», поиск игрока, боком — на весь экран. Компьютер (≥1100 px): трансляционный экран, режим «Кино» (T), клавиши 1–6 ←→ M A/O F ?. «Все столы» — главная фича, должна работать идеально на обоих; на финале (один стол) кнопка скрыта по задумке. На плитках — MMR, не ELO.

## 5. Регламент закрытия турнира
- Порядок — README, раздел «Как ЗАКРЫВАТЬ турнир» (официальная таблица mafgame 1:1, не пересчитывать самим).
- Если mafgame недоступен из облака: снять `/game_results` и `/results` через Vercel `web_fetch_vercel_url` (dovod-mafia.com/mafgame/…) и прогнать `freeze_tournament.js` локально с подменой загрузки на эти файлы — результат тот же, что у workflow «Закрыть турнир».
- Дополнительно при КАЖДОМ закрытии: проверить тиры — прогноз против итога (сколько каждого тира реально вышло в финал) и по итогам предложить, как дальше присваивать тиры.

## 6. Работа с репо
- Коммит → push в `main` = прод через ~1 мин. Перед пушем: `git pull --rebase`, проверка, что страницы открываются без ошибок консоли.
- Существенные правки документов (README/SPEC/этот файл) — с поднятием версии в шапке.
- Без явного «удали» ничего не удалять.

## 7. Закрытие сессии (Harvest по сайту)
Если в сессии менялся сайт или принимались решения — перед завершением, не дожидаясь команды:
1. Новые решения/правила/термины → дописать в этот `CLAUDE.md` (поднять версию, обновить оглавление).
2. Изменения структуры/данных/процессов → обновить `README.md` / `SPEC.md`.
3. Коммит + push.
4. Отдать Валерию 3–5 строк для лога сессий в Obsidian («что сделано / открыто / след. шаг») и список правил, которые нужно перенести в канон проекта «Мафия сайт».
